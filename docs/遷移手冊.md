# 遷移手冊：搬到專屬的 Google 帳號 / GitHub / Supabase

> 目的：把整套平台從開發用的個人帳號，搬到研究專用的帳號底下，並在搬家的同時把
> 「正式上線該做的安全設定」一次做完。
>
> 最後更新：2026-08-25

---

## 0. 先看這一段：搬家會搬什麼、不搬什麼

| 項目 | 搬不搬 | 說明 |
|---|---|---|
| 程式碼 | ✅ 搬 | 推到新的 GitHub repo |
| 資料庫**結構** | ✅ 搬 | `supabase/bootstrap/01_schema.sql`（已從現行資料庫產生並實測） |
| 參考資料（選單、問卷題庫、術語庫、部位碼、操作者…） | ✅ 搬 | `supabase/bootstrap/02_seed.sql` |
| **個案資料**（病人、照片、問卷回覆、治療紀錄） | ❌ **不搬** | 目前資料庫裡只有測試資料，新專案從零開始最乾淨 |
| 匯出金鑰、系統管理者 PIN | ❌ 不搬 | 這兩個是雜湊值，新專案請重新設定一次（見第 6 步） |
| `mrn_vault` / `mrn_vault_versions` 兩張表 | ❌ 不搬 | 2026-08-25 廢除的病歷號對照系統，程式已不再讀它們 |

**順序很重要**：`SUPABASE_SERVICE_ROLE_KEY` 一定要先設進環境變數，才能跑 `03_lockdown_anon.sql`。
反過來做，正式站會立刻讀不到資料庫。

---

## 1. GitHub

1. 用研究專用的 GitHub 帳號建一個**私有** repo（例如 `Keloid_platform`）
2. 在本機加上新的 remote 並推上去：

   ```bash
   git remote add keloid https://github.com/<新帳號>/Keloid_platform.git
   git push keloid main
   ```

   （本機目前已經有一個叫 `keloid` 的 remote，指向 `pskeloidcgh/Keloid_platform`。
   如果那就是要用的 repo，直接 `git push keloid main`；不是的話先 `git remote set-url keloid <新網址>`。）

3. 確認 `.env.local` **沒有**被推上去（`.gitignore` 已經擋掉，推完到 GitHub 上再看一眼）

---

## 2. Supabase：建新專案並灌結構

1. 用研究專用的 Google 帳號登入 Supabase，建立新專案
   - Region 選 **Northeast Asia (Tokyo)** — 與現行專案一致，從台灣連最快
   - 資料庫密碼**存到密碼管理員**，之後備份與 CLI 都要用
2. 進 SQL Editor，**依序**貼上並執行：

   | 順序 | 檔案 | 內容 |
   |---|---|---|
   | 1 | `supabase/bootstrap/01_schema.sql` | 45 張表、50 條外來鍵、25 個索引、2 個檢視、RLS 與 45 條政策 |
   | 2 | `supabase/bootstrap/02_seed.sql` | 384 筆參考資料（部位碼 88／問卷題目 78／術語 70／各式選單…） |
   | 3 | `supabase/bootstrap/04_storage.sql` | 建 `wound-photos`（**私有**）與 `term-library-images`（公開）兩個 bucket |

   > `03_lockdown_anon.sql` **先不要跑**，等第 5 步環境變數設好再回來跑。
   >
   > 這三支檔案是從現行資料庫自動產生的，並且已在一個乾淨的 schema 上實測跑過
   > （45 張表、45 條政策、參考資料全數寫入）。`supabase/migrations/` 那 72 支是歷史紀錄，
   > **新專案不要照著跑**——最早的幾支預設 base schema 已經存在，會失敗。

3. 到 **Project Settings → API** 抄下三樣東西：
   - `Project URL`
   - `anon` key（備援用）
   - `service_role` key（**正式要用的就是這把**，只放伺服器端，絕不進前端）

---

## 3. 檢查參考資料是不是自己要的

灌完 seed 之後，用新帳號的後台逐一看過這幾張清單，把不需要的停用、需要的補上：

- **操作者清單**（`/admin/operators`）：預設有 診間護理師／研究助理／試驗主持人／系統管理者 四位
- **醫師代碼**（`/admin/doctors`）：研究編號的前綴用它
- **放射科醫師**（`/admin/rt-doctors`）
- **ICD 常用碼**（`/admin/icd`）
- **治療類型與套組**（`/admin/treatments`）
- **追蹤時程範本**（`/admin/schedules`）

---

## 4. Vercel

1. 用研究專用的帳號登入 Vercel，**Import Git Repository** 選新的 repo
2. Framework 會自動偵測為 Next.js，不必改建置設定
3. 環境變數（Production ＋ Preview 都要設）：

   | 變數 | 值 | 備註 |
   |---|---|---|
   | `SUPABASE_URL` | 新專案的 Project URL | |
   | `SUPABASE_SERVICE_ROLE_KEY` | 新專案的 service_role key | **正式用這把**；沒有 `NEXT_PUBLIC_` 前綴，不會進前端 |
   | `SUPABASE_ANON_KEY` | 新專案的 anon key | 沒設 service_role 時的退路，可留可不留 |
   | `APP_SHARED_PASSWORD` | 自訂 | 全院共用的登入密碼（決策 #9） |
   | `GEMINI_API_KEY` | 新 Google 帳號申請的 key | LINE 衛教問答用；不設的話 AI 回答會停用，其餘功能正常 |
   | `LINE_RELAY_SECRET` | 自己產一組長亂數 | 要和 GAS 指令碼屬性填同一組 |
   | `LINE_OA_BASIC_ID` | 例如 `@abc1234` | 不設的話只顯示綁定碼、不產生掃碼連結 |

4. Deploy，開網址確認登入頁出得來

---

## 5. 收回 anon 權限（正式上線的關鍵一步）

**前提**：第 4 步的 `SUPABASE_SERVICE_ROLE_KEY` 已經設好，而且網站確定跑得起來。

1. 本機的 `.env.local` 也加上 `SUPABASE_SERVICE_ROLE_KEY`
2. 在新專案的 SQL Editor 跑 `supabase/bootstrap/03_lockdown_anon.sql`
3. 重新整理網站，確認個案列表、照片都還讀得到（service_role 會繞過 RLS）

跑完之後，就算 anon key 外流也開不了資料庫。這在病歷號與姓名改成明文存雲端之後特別重要。

---

## 6. 上線前的最後設定

1. **匯出金鑰**（後台 →「匯出金鑰」）：設一組，並把畫面上顯示的**救援碼抄下來存好**——
   那組救援碼只出現這一次，平台只留雜湊。沒有金鑰時，匯出檔的 Name / Chart No. 兩欄一律留空。
2. **系統管理者 PIN**（後台 →「系統管理者 PIN」）：設 4-8 位數字。設定後，切換成「系統管理者」
   要先輸入 PIN，維運工具（測試模式、清除測試個案、匯出金鑰）才打得開。
   忘記沒有救援碼——把 `app_settings` 的 `admin_pin_hash` 刪掉就回到未設定狀態。
3. **測試模式**（後台 →「測試模式」）：教育訓練期間打開，之後**記得關掉**。
   關掉之前先按「刪除所有測試個案」把 demo 資料清乾淨。

## 7. LINE 機器人（要用才需要做）

平台**不持有任何 LINE 憑證**，channel access token 只放在 GAS。完整步驟見 `gas/README.md`，
搬家時只有兩件事要改：

- GAS 指令碼屬性的 `PLATFORM_BASE_URL` 改成新的 Vercel 網址
- GAS 的 `LINE_RELAY_SECRET` 與 Vercel 環境變數的 `LINE_RELAY_SECRET` 必須是同一組

---

## 8. 搬完的驗收清單

- [ ] 新網址開得起來，用共用密碼登入得了
- [ ] 選操作者 → 落在各自的首頁
- [ ] `/admin` 六大類卡片都在，維運卡片只有系統管理者看得到
- [ ] 建一筆測試個案 → 病歷號、姓名存得進去，重複的病歷號會被擋
- [ ] 病人自填問卷 → 個案頁看得到身高體重、就診原因、病史與過往治療
- [ ] 拍一張照 → 照片顯示得出來（代表私有 bucket 的簽章網址正常）
- [ ] 匯出 Excel → 不輸入金鑰時 Name / Chart No. 留空；輸入正確金鑰後有值
- [ ] 跑完 `03_lockdown_anon.sql` 之後，以上全部再確認一次
- [ ] 舊專案（個人帳號的 Supabase / Vercel / GitHub）確定不再使用後再刪除或暫停
